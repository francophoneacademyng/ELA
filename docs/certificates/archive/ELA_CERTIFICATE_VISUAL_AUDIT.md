security settings were changed. All preview content is clearly-marked demo data.

## 1. Format

**PDF**, produced with `pdfkit` (`functions/ela-pdf.js`). There is a single,
unified template for all academies (`drawOfficialPdf`). A QR code is embedded
(no separate image deliverable). No HTML template is used for the certificate
itself; the only HTML is the public verification page (`verify.html`).

- A4 **landscape**, `margin: 0` (full-bleed background).
- Dimensions: `841.89 × 595.28 pt` (PDF points).

## 4. Logo

**None.** The PDF draws no image logo. The brand appears only as the text
wordmark `E-LEARN LANGUAGE ACADEMY` (top-center) plus the subtitle line. The
public `verify.html` page uses a text "ELA" badge, but that is not part of the
certificate PDF.

## 5. Layout / geometry

- Full-bleed forest-green background.
- Outer gold border: `rect(24, 24, W-48, H-48)`, stroke width `2`.
- Inner gold border: `rect(30, 30, W-60, H-60)`, stroke width `0.5`.
- QR code: top-right, `image(W-130, 90, width 90)`, caption `W-140 → 182`.
- Footer block (bottom third): integrity caption at `H-92`, hash value at
  `H-68`, verification URL at `H-52`.

## 6. Fields rendered on the certificate

In draw order:

1. `E-LEARN LANGUAGE ACADEMY` (institution wordmark, uppercase)
2. Subtitle — "E-Learn Language Academy — sole issuing institution of ELA certificates"
3. Certificate title (keyed by `certificateType`):
   - `completion` → "Certificate of Participation — ELA"
   - `achievement` → "Certificate of Achievement — ELA"
   - `certification` → "ELA Certificate — CEFR Level (Official)"
4. "This certifies that"
5. `studentName`
6. Type label (keyed by `certificateType`): "has attended… / has successfully completed… / has been certified at CEFR level by"
7. `academyLabel` + `" · Level "` + `cecrLevel`
8. `"Global score: {scoreGlobal}%"`
9. `"Issued: {issueDate}   ·   Valid until: {expiryDate}"`
10. `"Certificate No. {id}"`
11. Integrity caption + `{signatureAlgorithm} integrity hash: {signatureHash}`
12. `"Verify this certificate at {verificationUrl}"`
13. QR code → `verificationUrl`

**Fields stored in the document but NOT rendered on the PDF:** `institution`
(full name — only the wordmark is drawn), `signedBy` ("ELA Certification
Authority"), `language`, `skills`, `status`, `credentialId`, `programmeId`,
`examinationId`, `sourceQuizId`, `signature` (HMAC). There is **no
"Programme" field** printed — the closest is `academyLabel · Level cecrLevel`.

## 7. Certificate ID format

`ELA-{ACADEMY_CODE}-{CEFR_LEVEL}-{6 random chars}` — e.g. `ELA-FR-B1-8X92KD`.

- Generated by `generateCertificateId()` (`functions/ela-certificate-core.js`).
- Random alphabet: `ABCDEFGHJKMNPQRSTUVWXYZ23456789` (ambiguous chars removed).
- `credentialId` mirrors the `id`.
- Public verification regex: `^ELA-[A-Z]{2}-[A-C][1-2]-[A-Z0-9]{4,8}$`.

## 8. Verification URL & QR code

- `VERIFY_BASE_URL = https://elaacademy.ng/verify.html`
- `verificationUrl = https://elaacademy.ng/verify.html?id={id}`
- `verify.html` calls the public HTTPS endpoint `GET /verifyELACertificate?id={id}`
  (no auth, CORS open, per-IP rate limited).
- **QR code present** — embeds the `verificationUrl` (generated at 220 px,
  drawn at 90 pt width).

## 9. Signature area

**There is no visual signature area and no signature graphic.** The model
stores `signedBy = "ELA Certification Authority"`, but it is never drawn.
Instead, the bottom of the PDF shows the integrity-hash caption and the raw
`SHA-256` hash string. This is the only integrity evidence visible on the paper.

## 10. Security / integrity mechanism

- **SHA-256 integrity hash** computed over a canonical JSON of the certified
  fields: `id, certificateType, institution, academyCode, studentId,
  studentName, cecrLevel, scoreGlobal, issueDate, expiryDate, signedBy`
  (`canonicalJson` sorts keys, compact separators — deterministic).
- **HMAC-SHA256 authenticity (Phase 7)** over that hash using the server-only
  `ELA_CERT_SIGNING_KEY`. The key is never stored in Firestore, never shipped to
  the frontend, never committed. Without the key, certificates fall back to
  `authenticity: "integrity-only"` (no `signature` field) — historical certs
  remain verifiable.
- Firestore: `ela_certificates` is write-protected (Cloud Functions only);
  append-only events in `ela_certificate_events`.

## 11. What is publicly visible (verify endpoint)

`publicView()` returns only: `certificateId, studentName, institution,
academyLabel, cecrLevel, issueDate, expiryDate, status, valid`. The verify
response also adds `found, verificationState, integrity, authenticity,
integrityValid`. **Never exposed:** `studentId`, email, `skills`, `scoreGlobal`,
`signatureHash`, `signature`.

## 12. What requires `ELA_CERT_SIGNING_KEY`

Only the **HMAC authenticity signature** on new certificates. The key is not
needed for: PDF generation, SHA-256 integrity hash computation, or integrity
verification. **A preview PDF can be generated fully without the key** — which
is exactly what this audit did (the demo certificate is `integrity-only`).

## 13. Visual defects / observations

1. **No logo image** — the "official" PDF carries only a text wordmark.
2. **No signature block** — `signedBy` ("ELA Certification Authority") is never
   rendered; there is no visual signature/graphic.
3. **No "Programme" field** — only `academyLabel · Level cecrLevel` is printed.
4. **Type naming** — `completion` renders "Certificate of Participation", not
   "Certificate of Completion" (label mismatch vs. expected wording).
5. **Hash legibility** — the integrity hash is printed at 6.5 pt Courier and is
   effectively unreadable in print; the bottom third (caption + hash + URL) is
   crowded.
6. **Dates are raw** — `YYYY-MM-DD` with no localized/pretty formatting.
7. **No "DEMO" watermark** — demo status is conveyed only by the filename and
   the ID `DEMO-ELA-TEST`; the layout itself is unchanged (intentional).
